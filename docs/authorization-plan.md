# 身份、Agent 权限与 OBO 实施计划

状态：实施中，当前为 P0 链路验证与授权基础。核对日期：2026-10-20。基线：AgentOS Platform 0.7.0、AIOps 1.3.0。
已落地模型、SDK 判定、Actor 身份验证与 ExtMCP 适配，真实组件证据及原生边界见[链路验证](authorization-validation.md)。

## 目标与边界

建立用户、服务主体与执行 Agent 可验证的身份链路，在平台 API、原生执行入口、知识检索及下游工具调用处执行授权。
平台提供通用能力；业务资源、操作映射、目标系统权限配置及变更审批由方案包维护。

有效调用权限为：发起主体对资源的许可 ∩ Agent 能力上限 ∩ 本次执行授权 ∩ 目标系统账号权限。需要审批的操作另行满足审批条件。
用户能够调用某个 Agent，并不自动获得该 Agent 的连接器权限。Agent 的名称、提示词、工具注解及模型提供的身份字段只用于展示或输入。

首版覆盖人工对话、Agent 委派、机器触发、暂停恢复、OAuth 用户代办与服务凭据桥接。人员目录、自定义 IAM 控制台、调用预算及任意脚本的语义授权不在本次范围内。

## 现状与改动入口

| 现状 | 主要入口 | 目标 |
| --- | --- | --- |
| 工作空间共享 `subject`，`operate/manage` 固定开放 | `server/platform/access.ts`、`proto/agentos/console/v1/access.proto` | 已验证主体及针对资源的能力 |
| 原生调用使用固定 `X-User-Id` | `server/kagent/clients.ts`、`server/kagent/invoke-session.ts` | 由受信请求上下文映射的原生身份 |
| 会话与任务读模型缺少用户隔离 | `server/console`、`server/read-model` | 查询、详情、订阅及操作统一授权 |
| 协作 MCP 按服务密钥和角色校验 | `server/team-sessions`、`server/platform/guardrails.ts` | 工作负载身份绑定原生会话、任务和执行授权 |
| 环境工具按 Agent 映射长期服务凭据 | `charts/agentos/templates/gateway-auth.yaml`、`environments/templates` | 逐调用检查及显式连接器认证模式 |
| 审批独立于用户授权 | `server/governance`、方案包审批服务 | 精确操作审批与执行前权限复验 |

原生 `Session.creator`、`ResourceReference`、A2A Task、会话分享与生命周期 API 继续作为执行模型。
会话分享只提供相应的原生会话访问能力，下游执行还需独立授权。全局读模型可以保留内部索引，返回结果须先完成主体及资源过滤。

| 能力 | 采用方式 | 所属 |
| --- | --- | --- |
| 登录与身份 | 可选 OIDC 接入；OAuth2 Proxy 完成浏览器登录，openid-client 与 JOSE 校验受信身份 | 平台 |
| 资源关系与授权 | OpenFGA 官方 SDK、版本化模型与官方模型测试格式 | 平台 |

| 请求校验、Token Exchange、凭据注入 | agentgateway、Substrate 既有宿主机注入及必要的协议适配 | 平台与运行时 |
| 执行授权绑定 | 原生 Session/Task 标识、受信工作负载身份及最小持久化关联 | 平台与运行时 |
| 业务资源授权 | 将工具参数解析为明确的连接、操作与资源；提供资源 ACL 来源 | 方案包 |

身份提供方由部署方或目标运维环境提供并维护，平台校验站点配置的 OIDC issuer、audience 与角色声明。平台提供 `none` 与 `oidc` 两种显式认证模式；`none` 使用工作空间共享主体，`oidc` 使用已验证的用户主体。
授权判定直接服务平台 API、网关、调度与知识入口，执行不依赖浏览器或用户保持登录页面在线。
当前工作负载身份、网关和上游版本先验证再决定升级；新增 SDK 与组件锁定实施时已验证的最新稳定版本。

代码归属与部署位置分别确定：环境网关由平台提供并部署到目标环境；AIOps 的连接器适配与审批服务由方案包提供，可在环境侧运行。

| 凭据桥接 | 凭据引用、保管与注入机制、执行前授权、过期和撤销处理 | 账号初始化脚本、最小权限模板、连接器凭据绑定及轮换接线 | 实际用户/服务账号、原生权限、Secret/凭据存储和签发撤销能力 |

| 界面与审计 | 通用授权界面、拒绝/失效状态、主体与执行关联审计 | 业务文案、变更与工单展示、业务审计字段 | 原生账号操作日志、审计输出及留存配置 |
| 发布与接入 | 固定版本的运行时、契约/SDK、Chart、迁移与通用接入工具 | 平台依赖升级、方案配置、环境初始化与业务回归 | 站点参数、证书/密钥、部署权限、资源配额及目标权限验收 |

平台交付通用机制与可验证执行边界，AIOps 交付业务规则和适配，环境交付实际信任、账号、权限与基础设施。
平台可以对接企业已有身份提供方；控制面身份服务与 OpenFGA 的部署、存储和运维属于平台基础设施，按平台发行与站点接入流程交付。
目标环境可复用受信身份提供方；跨身份提供方或 realm 的用户映射与令牌交换按连接器实际能力单独验收。
环境管理人员确认真实账号、资源范围和信任配置；AIOps 提供的自动化脚本负责将已确认配置落实到目标系统。

业务资源映射覆盖调用参数与实际返回范围。列表、搜索和批量工具优先利用目标 API 或成熟 MCP 的原生过滤，必要适配在方案包内完成，内容进入模型前落实用户与执行授权范围。
桥接模式下，用户许可来自受管业务 ACL，目标系统识别服务账号；原生账号权限只表示该服务账号的上限。目标环境的 API 接受相应用户令牌并执行用户授权后，连接器才标记为 OAuth 用户代办。

以用户请求重启某环境 `payments` 命名空间的 Deployment 为例：平台验证发起者、Agent、执行授权及审批条件；AIOps 将工具调用解析为具体环境、资源和重启操作，执行变更规则；环境网关应用通用授权，Kubernetes 再按实际用户或服务账号的 RBAC 判定请求并生成原生审计。

目标环境接入时提供以下材料，由 AIOps 接线配置引用：

- 环境与资源标识、网关/MCP/API 地址、TLS 信任及允许的网络路径。
- 每个连接器实际支持的认证模式；OAuth 的签发方、受众和权限范围，或用户/服务账号的凭据引用。
- 已落实的原生账号权限、可操作资源、ACL 来源及审批人权限。
- 凭据签发、保管、轮换、撤销的责任主体与运维入口。
- 原生审计出口及允许/拒绝操作的真实验收证据。

## OBO 提供方能力

按 [Keycloak 官方文档](https://www.keycloak.org/securing-apps/token-exchange)，Standard Token Exchange V2 可用于用户目标令牌交换；包含 `act` 的委派能力目前属于 Preview。
生产首版采用稳定交换能力，Agent 归因通过平台受信绑定与审计完成。要求目标系统独立验证 `sub` 与 `act` 的连接器，须另外通过身份提供方的稳定委派能力验收。
MCP 资源 URL 与目标 `audience` 显式映射；Keycloak 不支持的 `resource` 参数按提供方能力处理。

## 身份与契约

- 人类主体以 OIDC `issuer + sub` 唯一标识；机器主体来自验证后的工作负载或 OAuth 客户端身份。邮箱、显示名与客户端自报请求头不承担身份认证。
- 平台资源权限区分 Agent 调用与配置、会话读取与操作、连接使用与凭据管理、知识检索与维护。工作空间管理权限单独授予；Agent 配置编辑权不包含授权或凭据策略编辑权。
- Agent 能力上限由受控策略维护。本次执行授权绑定发起者、执行 Agent、原生 Session/Task、允许的连接/操作/资源及有效期；子执行关联父授权且权限与期限只能收窄。
- OpenFGA 保存资源关系与有效授权；原生持久化状态保存执行关联。授权生效、失败补偿、幂等与恢复按统一生命周期处理；未完成绑定的执行保持不可调度。
- 外部身份复用 OIDC 声明；运行资源复用 kagent 官方 proto；平台仅以 proto 定义缺失的执行授权关联及必要 API，生成所有语言契约。策略采用 OpenFGA 原生模型。
- 上下文与鉴权输入由服务端生成；工作负载身份、会话和任务须相互校验。授权 ID 只用于关联，持有 ID 本身不构成调用权限。
- 登录采用 Authorization Code + PKCE，平台服务端保存令牌，浏览器仅持有 `HttpOnly/Secure/SameSite` 会话 Cookie；状态校验、CSRF 与刷新交由成熟库处理。
- 登录会话和凭据存储的具体适配在 P0 定稿：复用受控服务端存储及现有 Secret/注入能力，明确加密、TTL、刷新串行化与清理职责；刷新令牌和目标凭据留在受信边界内。

## P0：链路验证与设计定稿

- [ ] 验证 kagent 对身份头的信任边界、`Session.creator`、分享权限及全入口鉴权；列出原生 gRPC、A2A、MCP 与管理网络入口，确定唯一受信注入方。
- [ ] 在现有 Substrate 版本验证 Actor 身份与会话、任务的绑定；覆盖任务 ID 生成前的启动、多轮会话、委派、并发任务、快照恢复、重启及后台执行。复用现有 Kubernetes 工作负载身份，明确宿主机可注入且模型不可伪造的上下文。
- [x] 验证 agentgateway 固定版本在实际 `tools/call` 上获得工具名、规范化参数和受信 Actor/Session 上下文；采用官方 ExtMCP 接点，验证越界请求未到达工具后端。执行 grant 与 Task 关联在原生边界项继续验证。
- [ ] 用两个用户、两个 Agent、两组资源验证 OpenFGA 模型，覆盖调用/配置分离、资源交集、父子授权、过期与撤销；确定模型版本、一致性策略与关联存储方式。
- [ ] 验证 Keycloak 交换的 `sub/aud/scope`、客户端限制及显式下放权限；核对默认 client scopes、audience mapper 与 `full_scope_allowed`，验证未授权 scope/audience 被拒绝。对长期任务实测显式续期授权、刷新、再认证及注销后的本地失效处理。
- [x] 选定 Keycloak 原生用户 API 与 NetBox 只读 Token 桥接作为首批接入，分别验证用户令牌与服务 Token 的原生读写边界。生产连接器的用户关联、资源过滤与凭据生命周期继续按 P3 验收。
- [ ] 定稿最小 proto 变更、登录会话/凭据存储、授权生命周期、撤销语义、模型版本与原生必要补丁；补丁在 `runtime/` 固定并优先提交上游。

交付：可重复运行的集成验证、认证模式清单、授权模型与接口差异、短期架构决策记录。
准入：执行身份跨生命周期可验证，工具调用可以逐次拦截，授权状态可持久恢复。缺失原生能力先修补并复验，随后冻结契约进入 P1。

## P1：登录、资源权限与数据隔离

- [ ] 接入 OIDC 与服务端会话；验证 issuer、签名、audience、state/nonce；初始化工作空间管理员的显式主体绑定。身份或策略服务不可用时拒绝受保护操作。
- [ ] 用已验证主体替换 `workspaceContext` 的固定权限和原生客户端的共享用户；服务身份独立处理，机器身份不模拟人类。
- [ ] 接入 OpenFGA 模型与官方 SDK，覆盖控制台 RPC、管理、测评、协作 MCP、原生入口及知识服务；凭据管理和策略管理仅开放给对应权限。
- [ ] 按主体过滤任务、会话、审批、记忆、测评产物与引用；分页游标、缓存和 SSE 订阅绑定主体与授权范围。权限变化时复验持续订阅。
- [ ] 知识 ACL 在召回内容进入模型之前生效；跨会话记忆、生成物、追踪链接和 Langfuse 可访问范围采用一致的资源边界。

准入：用户甲无法通过列表、已知 ID、分页、订阅、直接原生入口或共享缓存读取和操作用户乙的数据；UI 可见性与服务端判定一致。

## P2：执行授权、委派与撤销

- [ ] 每次执行生成受限授权并绑定原生生命周期；多轮会话分别检查当前发起者与当前执行权限。授权输入来自明确资源选择或已审计策略，模型只能提出权限申请。
- [ ] `create_session`、`invoke_session`、`dispatch_session`、自动续接与后台任务传递受信关联；Agent 切换、委派及会话分叉生成受限子授权。
- [ ] 机器触发、Temporal 和测评作业使用显式服务主体与资源许可；创建者作为审计信息保留。人类发起的后台任务保留原授权边界，过期后等待重新授权。
- [ ] 到期、撤销、取消与完成阻止后续调度、工具调用及令牌续期；父授权失效联动子授权。服务端时间作为过期判断输入，快照恢复重新解析当前授权状态。
- [ ] 执行检查采用 OpenFGA 较高一致性读取，授权缓存与撤销成功响应保持一致：撤销成功后开始的鉴权拒绝该授权及其子授权。已发送的请求保留结果核验流程，撤销不等于撤回目标系统已执行的副作用。

准入：具有高权限的子 Agent 无法扩大父授权；其他 Actor 无法借用授权 ID；重启、重试、暂停恢复与后台执行均不能复活已失效授权。

## P3：网关执行与连接器 OBO

连接器声明一种认证模式，平台按其实际能力展示身份语义：

| 模式 | 目标系统身份 | 执行要求 |
| --- | --- | --- |
| OAuth 用户代办 | 发起用户；目标支持时包含经验证的 Agent actor | 目标令牌交换、固定目标 audience、最小 scope、目标原生用户授权 |
| 用户 API Token | Token 所属用户，Agent 归因由平台记录 | 服务端凭据保管、用户绑定、资源与执行授权检查 |
| 服务身份桥接 | 连接器服务账号 | OpenFGA 明确用户资源许可，网关强制操作边界，目标限制服务账号权限 |

- [ ] 每次调用先验证主体、Agent、执行关联、连接、操作和目标资源，再换取或注入凭据；工具参数经过结构化解析，目标由连接器配置限定。
- [ ] 使用 agentgateway 原生 Token Exchange 与官方提供方能力，复用宿主机凭据注入；兑换客户端仅允许指定 audience/scope。目标令牌不透传到其他受众。
- [ ] 凭据缓存按主体、actor/执行授权、连接、目标 audience 与 scope 隔离；缓存命中仍须检查授权，授权失效阻止使用缓存和刷新。
- [ ] 凭据只在可信代理、宿主机与目标之间流转；提示词、工具参数、运行时可读环境、浏览器响应和日志使用不含令牌的引用或脱敏信息。
- [ ] 按连接器验证 MCP 授权元数据、目标令牌校验及错误处理；OAuth 不可用返回重新认证或无权限状态，认证模式变更由受控配置完成。
- [ ] 方案包提供资源解析与 ACL 接线；首批工具限于可明确判定操作和目标的 API。终端、通用脚本工具需有目标账号与执行沙箱层面的可验证边界后接入。

准入：真实 OAuth 目标正确识别用户，NetBox 桥接目标仅接受授权范围内请求；错误 audience、跨资源参数、伪造身份、越界 scope 和跨执行凭据复用均被拒绝。

## P4：审批、界面与审计

- [ ] 原生 HITL 和外部审批在恢复、准备执行及实际调用前重新验证当前授权；审批绑定原生工具调用、参数摘要与目标资源，参数改变重新审批。
- [ ] 保持平台对 `ApprovalService` 的通用依赖；AIOps 将验证后的发起者与 Agent 归因接入自身工单、执行准备和结果核验。
- [ ] `AccessProfile` 展示必要身份与资源能力；页面提供当前有效授权、目标范围、失效原因、撤销和重新认证入口。登录使用身份提供方页面；其余复用 shadcn/ui 与现有交互组件。
- [ ] 通过现有 OTel 管线输出主体、执行 Agent、授权 ID、原生 Session/Task、资源、决策与审批关联；配置保留期、访问权限和敏感字段过滤。鉴权拒绝同样可追溯。
- [ ] 原生执行历史和结构化审计事件保留事实，OpenFGA 管理当前有效授权；完成后清理授权不影响历史追溯。审计采集故障的执行策略在发布配置中明确。

准入：批准无法绕过当前用户权限、Agent 上限、已撤销授权或目标系统权限；授权变更和实际工具调用可以关联，用户界面不暴露凭据。

## P5：迁移与生产切换

- [ ] 平台发布 proto、生成 SDK、运行时补丁、镜像、Chart 与环境接线；AIOps 同步更新平台依赖、连接器认证模式、ACL 和审批接线，迁移范围仅包含本次版本变更。
- [ ] 盘点旧会话、任务、知识、机器主体和服务密钥；历史共享身份数据显式归入历史服务主体，由指定管理员按记录授权。迁移不推断历史真人身份，原始 `creator` 与执行事实保留。
- [ ] 备份原生数据库、授权模型、关系及部署配置；暂停新写入并结束或取消旧执行，存量审批重新验证。迁移使用稳定 ID，具备幂等和完整性检查。
- [ ] 一次切换登录、平台授权、原生入口、网关及连接器；撤销被替代的共享密钥与旧信任路径。新的静态服务凭据只能通过受控桥接链路使用。
- [ ] 核验身份服务不可用、策略不可用、凭据过期、实例重启与恢复；回退保持已验证身份和授权边界，恢复写入前完成授权及数据一致性核验。
- [ ] 发布后验收人工对话、委派、HITL、外部审批、机器触发、测评与真实目标调用；环境清单维持当前有效环境，核对站点入口和运行版本。

准入：P0—P4 验收通过，认证与授权覆盖矩阵无绕过入口；生产从开放访问一次迁移到统一授权，同一版本只有一套有效身份与授权路径。

## 验证与提交顺序

| 验证层 | 必须覆盖 |
| --- | --- |
| 授权模型 | 两用户、两 Agent、两资源；调用/配置分离；Agent 上限、父子交集、过期和撤销 |
| API 与读模型 | 越权列表/详情/分页/缓存/SSE、知识召回、管理与测评、幂等重试的主体隔离 |
| 原生运行时 | 伪造身份、借用授权、并发任务、委派、后台执行、快照、重启与恢复 |
| 网关与目标 | 实际 MCP 调用、错误 audience、scope 扩大、资源参数替换、令牌缓存与刷新隔离 |
| 审批与故障 | 授权撤销后批准、参数改变、恢复时过期、授权服务故障、在途副作用核验 |
| 浏览器与发布 | 官方登录流程、越权入口、授权和重新认证；迁移幂等、旧凭据失效与部署冒烟 |

提交顺序：链路验证与契约 → 登录/授权模型/数据隔离 → 执行绑定与委派 → 网关/连接器 → 审批/UI/审计 → 迁移与联合发布。
各阶段运行相应模型、API 与集成检查；涉及 proto 时重新生成并验证 SDK。发布前运行 `npm run verify`、浏览器测试、Chart/环境校验及真实原生运行时与目标系统验收。
fake kagent 与模拟 OAuth 服务用于快速回归；运行时身份、目标用户权限和真实凭据生命周期由实际组件验收。
