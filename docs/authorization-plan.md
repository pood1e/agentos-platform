# 逐资源授权范围

当前授权由应用角色、原生 Actor 身份与执行委派链组成，运行边界见[执行授权](execution-authorization.md)。
平台资源的读取与管理使用 proto 中的能力目录；目标操作按原发起人权限、Agent 工具绑定和环境原生权限共同收窄。

## 后续扩展

逐资源业务 ACL 适用于同一工作空间内按团队、资源和分享关系进一步隔离的场景，独立于当前维护面收敛重构。

| 边界 | 扩展内容 |
| --- | --- |
| 资源 | 稳定标识及团队归属，区分读取、调用、配置和授权管理 |
| 关系 | 所有者、成员、只读分享与资源继承 |
| 执行 | 绑定授权版本与父子资源子集，撤销后拒绝后续调用 |
| 读取 | 列表、分页、缓存、订阅与知识检索统一按主体过滤 |
| 凭据 | 继续复用原用户 OBO；服务身份桥接遵守相同资源上限 |
| 审计 | 原生执行历史与结构化决定关联，授权变更保留审计记录 |

## 组件边界

身份提供方由部署环境提供，平台复用 OIDC 与原生令牌交换。关系授权实施时采用成熟的关系授权组件，
结合官方模型、SDK 和一致性语义验证；执行状态继续保存在原生持久化接口中。

OpenFGA 早期实验未接入运行链路，模型与 SDK 在 0.27.0 移除，历史实现在 `40e4bc1`。
Substrate 原生基础设施授权与平台业务 ACL 分属各自资源域。

## 验证要求

- 两个用户、两个 Agent 与两组资源覆盖调用和编辑分离、分享、父子授权与撤销。
- 管理 RPC、协作 MCP、原生入口、读模型与持续订阅使用一致的资源范围。
- 授权服务不可用时拒绝执行；确认撤销后开始的鉴权拒绝该授权及后代授权。
- 后台任务保留原发起人和离线授权，审批与委派均不能扩大权限。
- 支持原用户 OBO 的目标保留用户身份；服务身份桥接在内容进入模型前执行资源限制。
- 取消、令牌轮换、并发、重启及外部副作用后的崩溃通过真实链路验证。
